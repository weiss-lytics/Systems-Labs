Design Rationale
A·01
Two-row topbar
Splitting primary actions (row 1) from secondary context (row 2) reduces cognitive load. The energy mode selector and stats live in the quieter second row — present but not competing.
A·02
Today's Focus sidebar
Acts as a daily briefing panel — not just backlog storage. It surfaces due today, active work, and high priority without requiring the user to scan all five columns.
A·03
In Progress is the widest column
Asymmetric column widths reflect workflow priority. Your active work deserves the most visual space. Backlog and Complete are intentionally compact — they're peripheral states.
A·04
Priority as left border stripe
One 3px stripe communicates priority without a noisy label. High = sakura rose. Medium = warm amber. Low = sage. Information density stays low, signal stays high.

A·01
Column picker as pills
No dropdown — a scannable pill row. You see all 5 options at once and tap. Faster than a select menu for 5 or fewer options.
A·02
Blocker reason field
Conditionally revealed only when Blocker column is selected. Reduces form complexity — context determines what you see.
A·03
Progress bar input
A 0–100% field that renders as a mini progress bar on the card. Visual feedback motivates completion. Optional — defaults to 0.
A·04
Enter to save
Title field responds to Enter key. Power users never need to reach for the mouse. Reduces friction for fast task entry.

Screen 05 · Pomodoro Timer

Focus Without Pressure

A dedicated timer modal that links sessions to tasks. Calm, minimal, purposeful.

P·01
Circular ring timer
SVG progress ring depletes smoothly. Rose stroke for Focus, sage for Break. Visual state change is immediate — you know which mode you're in at a glance.
P·02
Session dots
4 dots track completed focus sessions. After 4 sessions, a long break is encouraged. No configuration required — the dots self-explain.
P·03
Task linking
A select dropdown links the timer to a specific open task. This creates intentionality — you declare what you're working on before the session starts.
P·04
3 modes
Focus (25 min), Short Break (5 min), Long Break (15 min). Switching mid-session is blocked — a gentle forcing function for staying in the zone.
Finish State
When a session ends, the ring glows, the title tab blinks "🍅 Time's up!", and the session dot fills. No aggressive sound or popup — respectful of deep work states.

System Thinking

How Haru moves data — from user intent to persisted state. Entirely client-side, intentionally constrained.

01
User Intent
Every interaction starts with a human decision: capture a thought, move a task, start a timer, switch energy mode. Haru presents minimal friction to each action.

Constraints as Features
C·01
Single HTML file
No build step, no deploy pipeline, no dependency rot. Open the file, it works. Shareable as an email attachment. The constraint is the product.
C·02
No frameworks
Vanilla JS forces explicit, readable code. Every DOM operation is intentional. No magic, no black boxes — what you see is what runs.
C·03
localStorage only
Your data never leaves your machine. No accounts, no sync, no servers. Privacy by architecture — not by policy.
C·04
CSS variables for theming
Dark and light mode via 30 CSS custom properties. One dataset.theme = 'dark' flips the entire visual system. No class toggling, no duplication.
