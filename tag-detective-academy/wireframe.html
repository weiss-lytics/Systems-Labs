Design Decision
Byte mascot appears immediately on home — establishes personality before any content. Stats are prominently visible to create a progress hook even at 0 XP ("empty state = opportunity").
UX Decision #1
Hero CTA is "Start Investigation" not "Sign Up" — task-framing from word one sets the detective tone and reduces perceived commitment.
UX Decision #2
4 stat cards visible immediately (XP, Cases, Streak, Rank) creates psychological investment even for new users. Empty is motivating, not discouraging.
The Byte Mascot
CSS-only chibi detective with float + blink animations. Never blocks content. Gives contextual hints per screen. Clickable for tips.
Information Architecture Note
The welcome screen serves 3 functions: (1) Identity establishment via detective metaphor, (2) Status display for returning users, (3) Clear entry point to the core loop. Navigation is secondary — the hero CTA drives the primary action.
Accessibility Considerations
Stat cards use semantic HTML. CTAs have descriptive aria-labels. Byte mascot has role="button" with aria-label. All interactive elements have visible focus states. Contrast ratios meet WCAG AA throughout.

Design Decision
Colored top-border on cards (green/amber/red) provides instant difficulty scanability without reading labels. XP rewards are always visible to motivate case selection by ambition level.
Card Architecture
Each case card shows: difficulty, XP reward, topic tag, and progress. Users choose cases by their own risk/reward calculation — this is intentional self-pacing.
Progressive Disclosure
Case descriptions are brief — details revealed in investigation. This preserves the mystery. Don't spoil the puzzle on the case board.
Difficulty Encoding
Color stripe at card top (green/amber/red), badge label, and XP reward all communicate difficulty independently. Three redundant signals for accessibility.
Solved State Behavior
Solved cases show a ✓ SOLVED badge, reduced opacity (0.75), and "Review Case" CTA. Progress bar fills to 100%. This allows revisiting without penalizing completion — reinforcement is positive.
Future: Dynamic Case Loading
The case grid is designed for dynamic content — cases can be loaded from a CMS or API. Card structure remains identical regardless of content. This screen scales to 50+ cases with virtual scrolling.

Layout Rationale
Two-column layout: 2/3 for evidence (the work), 1/3 for context + hint. The event log uses dark terminal styling intentionally — it's a real developer artifact. This creates credibility and teaches real debugging patterns.
Clue Selection UX
Clue cards are toggle-selectable. Selected state shows accent border + checkmark. Counter ("2 of 6") creates completionist pull. No required minimum — users self-direct inquiry.
The Event Log
Dark terminal-style log teaches real GA4 debugging patterns. Color-coded: gray = normal, green = success, red = error, amber = warning. Authentic developer experience.
Cognitive Load Design
Byte's hint is always visible but subtle. Evidence board is scannable before deep reading. Case summary keeps context. Nothing requires scrolling to find key info.
Mobile Adaptation
Below 768px: two-column layout stacks vertically. Sidebar moves below evidence. Clue grid collapses to single column. Event log height is capped at 120px. CTA remains full-width and sticky.
Why Clue Selection Matters
Asking users to actively identify relevant evidence before answering builds real analytical thinking. It's not just a UI affordance — it mirrors the actual debugging workflow: observe → hypothesize → test → conclude.

CASE #001 — Challenge
🧩 Solve the Mystery
Why are purchases missing from GA4?
Case Context
Console shows: "ReferenceError: dataLayer is not defined" on /order-confirmation. The GTM container fires, but the purchase event never appears in GA4.
A
The purchase event trigger in GTM has a typo in the event name
B
The dataLayer was not initialized before the GTM snippet on the confirmation page
C
GA4 property ID was changed in the configuration tag
D
The checkout page is blocked by an ad blocker on the test device
✅ CORRECT ANSWER
The new checkout flow removed the window.dataLayer = window.dataLayer || [] initialization. Both the push AND the GTM snippet need dataLayer to exist first.
💡 BYTE'S HINT
Feedback Design
Correct answer highlighted in green immediately. Wrong answers dim (opacity 0.55) rather than showing a red "wrong" — this avoids shame. Explanation always follows the answer to close the learning loop regardless of outcome.
Challenge Mechanics
One correct answer per challenge. Selection locks all options. Feedback appears 300ms after selection for perceived deliberation. Then auto-advances to Case Closed after 1.8s.
Partial Credit
Wrong answers still award 25 XP ("partial credit"). This prevents frustration loops and keeps users from abandoning after a mistake. Learning = progress.
Context Box
The context box repeats the key evidence from investigation. Users shouldn't need to go back — everything needed to answer is visible on this screen.
Distractor Design
Distractors (wrong answers) are plausible — they're real GA4/GTM issues a developer might confuse. This tests understanding, not just memory. Option A (typo) and C (property ID) are common real-world mistakes.

Emotional Design
The stamp animation is the emotional climax of the entire user journey. It must feel satisfying — the overshoot cubic-bezier creates a physical "thwack" sensation. Confetti appears simultaneously via JS canvas particles. Then calm settles into the learning summary.
Celebration Design
Stamp animation uses scale + rotate overshoot. Confetti is CSS/JS only (canvas particles). Green = success (universally understood). The stamp rotates slightly to feel handstamped, not digital.
Rank Up Moment
If completing this case triggers a rank change, a secondary animation ("Analyst → Inspector!") appears above the stamp. This is the biggest motivational moment in the app.
Learning Summary
3–4 bullet points teach the core lesson. This is the "so what" — it closes the loop between puzzle-solving and real-world knowledge. Always present even for wrong-answer cases.
XP Animation
XP counter animates from 0 to earned amount (+100) over 800ms. A "+100 XP" popup toast also appears in the top-right corner. The nav stat counter also animates to reflect the new total. Three reinforcement signals.

Information Architecture
Academy complements cases — both teach GA4/GTM but through different modalities. Cases = discovery learning. Academy = systematic coverage. Users can choose their path. Some content unlocks via rank to create aspiration.
Accordion Pattern
One section open by default (current). Others collapsed to reduce cognitive load. Progress visible in collapsed state — no need to expand just to check progress.
Lesson States
4 states: Done (green ✓), Active (blue ▶), Locked (gray 🔒), Default. Locked content shown but dimmed — aspirational pull, not hidden. Users know what's coming.
XP Visibility
Every lesson shows XP reward. This creates micro-motivation per lesson. Higher XP lessons are harder/longer — users can self-select difficulty within the curriculum.
Rank-Gated Content
Advanced sections (Data Layer, Variables) unlock at specific ranks. This prevents overwhelm for beginners while giving experts clear progression milestones. The locked state shows the unlock requirement — never a mystery.

💾 Session Storage (Current) → Future: Persistence Layer
Phase 1 (Now)
JavaScript memory only. State resets on page close. No backend required. Fully offline.
Phase 2 (Future)
localStorage for persistence. Optional user accounts. Leaderboards. New case unlocks via API.
Architecture Philosophy
Zero dependencies. Pure HTML/CSS/JS. Works offline. State lives in memory for session. This enables instant deployment — no server, no build, no auth required.
Data Layer Pattern
A single `state` object is the source of truth. All UI derives from state. No two-way binding — mutations trigger re-renders explicitly via helper functions.
Performance Budget
Target: <100KB total. No external requests. CSS animations use transform/opacity only (GPU composited). Confetti uses requestAnimationFrame with auto-cleanup.
Future Extensibility
Data structures (CASES[], ACADEMY_SECTIONS[]) are plain JSON — easy to move to a CMS or API. The render functions are decoupled from data shape.
Key Design Principle
The app is intentionally stateless between page loads in Phase 1. This is a feature for the prototype — it means users can share the file, open it anywhere, and start fresh without setup friction.
